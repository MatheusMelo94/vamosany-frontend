#### Finding RV-0035: The frozen footer changed (text and 8 links) with no DDR to record it

- **Convention citation:**
  - per `design-conventions.md § DDR Template`: a DDR is required for "any feature that conflicts with the constitution's non-goals". Constitution v1 § Non-Goals 1 says a visual change on a live surface needs a DDR (repeated in CLAUDE.md: "Mudança visual exige DDR").
  - ADR-0006: the footer is frozen.
- **Issue:**
  - DDR-0012 § 4 says "O rodapé não muda", and DDR-0013 § Neutral keeps the footer column heading as text.
  - The branch still changes the visible footer string on every page that has the footer, including the landing. It also turns the 8 Guías entries into real links.
  - The user's decision exists only in plan Q1, `tasks.md:315`, the commit body of `e0446e9` and the QA handoff.
  - The change is right (spec AC 5 "nowhere in … the site"), and it is the only landing change the user expected. But the durable record of record is missing. The landing's `full-reduced-motion-*` baselines will move because of it.
- **Remediation:** Record the decision in a short DDR-0014 (DDRs are immutable, so DDR-0012 cannot be edited): "Footer Guías column follows the menu: 'Caminar por New York', entries link to the guides". Reference it from DDR-0012/0013 and the spec. No code change.
- **Routed to:** UX Strategist (draft); the user approves.

#### Finding RV-0036: AC 12, "Reduced: no lift, the border change remains", has no border change to remain
- **Location:** `features/guias/components/guide-card.tsx:27`
- **Convention citation:** per `design-conventions.md § Motion Principles` (state change paired with a non-motion cue); spec AC 12 and § Motion Intent ("2px lift on hover … and a border/background change").
- **Issue:**
  - I checked in the browser at 1280. With motion on, the card lifts (`translate: 0px -2px`).
  - The border colour is the same before and after hover (`rgb(1, 0, 0)` both times), and the background does not change.
  - The only cue that survives reduced motion is the title underline (`group-hover:underline decoration-brand`). That is a visible cue, but it is not what AC 12 or the Motion Intent state.
  - The pager cells do have a border change (`hover:border-ink`).
- **Remediation:** Choose one:
  - (a) Add a non-motion hover change to the card that keeps tokens, such as `hover:bg-surface-1` on the text area or a `brand` decoration already in use, so AC 12 holds as written. Frontend Engineer.
  - (b) Amend AC 12 to "the title underline remains". UX Strategist.
- **Routed to:** UX Strategist (decide), then Frontend Engineer if (a).

#### Finding RV-0037: At 200% text-only, a 1280 window collapses to one column, against the spec's States Matrix
- **Location:** `app/globals.css:76-78` (rem container widths), `features/guias/components/guide-page.tsx:45`
- **Convention citation:** per `design-conventions.md § Spec Shape` (the spec is the contract; deviations are recorded); spec § States Matrix, "200% text size" row ("Text-only 200% at a wide window keeps 2 columns because the aside width is in rem").
- **Issue:**
  - `--container-guide-aside: 60.0625rem` is in rem, so at a 200% root font size the two-column layout only starts at about 1,922 px. I measured at 1280 with `html{font-size:200%}`: `<details>` shows and the aside is static.
  - AC 41 still passes: no loss and no overlap. Guías content adds no horizontal scroll. The 1,528 px `scrollWidth` comes from the pre-existing desktop navbar row on every page, confirmed on `/` and `/sobre-mi`.
  - The only record of the divergence is a line in the QA handoff ("Interpretation"). The plan (D-9) does not mention it, and the spec says the opposite.
- **Remediation:** Amend the spec's 200% row to describe the one-column result. It is arguably the better outcome: one reading column at a large text size. Or, if two columns are wanted, the Architect switches the aside query to px-equivalent widths (container queries in `px`, with a justification comment). Recommend amending the spec.
- **Routed to:** UX Strategist (spec text), Frontend Architect (if the layout should change).

#### Finding RV-0038: The fidelity test strips bold and italic, so AC 27's "bold/italic are preserved" is not automated
- **Location:** `features/guias/__tests__/support/fidelity.ts:18-25` (`clean` removes every `*`), `features/guias/__tests__/support/plain-text.ts:18-28` (`inlineText` flattens `{ b }`/`{ i }`)

  - Make `docUnits` normalize the Doc's D5 noise to the same canonical form: collapse `****` and the `**…**` wrapper that spans a sub-label line break, keeping inner `**x**` runs.
  - Add a "proves it can fail" case that drops one `{ b }`.
- **Routed to:** Frontend Engineer.

#### Finding RV-0041: Component tests assert Tailwind class names as stand-ins for layout and state
- **Location:**
  - `features/guias/__tests__/guide-card.test.tsx:47-78`
  - `guide-page.test.tsx:26`, `:134-147`
  - `guias-home-page.test.tsx:77-87`
  - `key-facts.test.tsx:40-47`
  - `guide-toc-details.test.tsx:58-61`
  - `guide-heading.test.tsx:87-103`
- **Convention citation:** per `frontend-architecture-conventions.md § Engineering Workflow` ("Test names describe behavior, not implementation"); Reviewer Test Quality audit (assertions on class names are implementation detail).
- **Issue:**
  - Examples: `toContain("hover:-translate-y-0.5")`, `"@guide-aside:tall:sticky"`, `"grid-cols-1"`, `"aspect-3/2"`.
  - These tests break on a harmless refactor, such as a class rename or a move to a utility. They pass even if the CSS does not do what the name suggests, for example a misspelled container name.
  - The real behaviors are already covered by geometry and computed-style checks in `toc.spec.ts`, `responsive.spec.ts`, `home.spec.ts` and `a11y.spec.ts`.
- **Remediation:** Remove the class-name asserts whose behavior a Playwright spec already measures. Keep the few that guard a contract no e2e reaches, and rename them as CSS contract tests (as `styles.test.ts` already does).
- **Routed to:** Frontend Engineer.

#### Finding RV-0042: Two menu e2e tests run 12 full navigations each inside the default 30 s budget, and time out under load
- **Location:** `tests/e2e/guias/menu.spec.ts:58-69`, `:71-82`
- **Convention citation:** per `frontend-architecture-conventions.md § Engineering Workflow` (route-level behavior in Playwright); Reviewer Test Quality audit (specs independent and deterministic).
- **Issue:**
  - Each test loops over the 12 items: `goto('/')`, open the menu, click, assert the URL. That is 12 landing loads, including the landing's GSAP, in one test.
  - At `--workers=2` on a loaded host, both timed out on all three projects.
  - `:58` passed alone in 25.3 s of 30 s. Any CI slowdown turns this into a flake, and one failure hides which item broke.
- **Remediation:** Parametrize the loop so there is one test per item: `for (const [title, slug] of ITEMS) test(\`… ${title}\`, …)`. Or at least call `test.slow()`. Starting from `/guias` instead of `/` would also drop the landing's motion cost, and the menu is the same on every page.
- **Routed to:** Frontend Engineer (author); QA Engineer informed (`tests/e2e` is QA-owned).

### NIT

#### Finding RV-0043: Arbitrary values without a justification comment
- **Location:** `features/guias/components/guide-page.tsx:46` (`max-w-[68ch] text-[1.05rem] leading-[1.6]`), `features/guias/components/guide-heading.tsx:68` (`[--train:0%]`)

#### Finding RV-0044: Hard-coded `duration-150` instead of the motion token
- **Location:** `features/guias/components/guide-card.tsx:27`, `features/guias/components/pager.tsx:9`
- **Convention citation:** per `frontend-architecture-conventions.md § Animation (GSAP 3)` ("Durations and easings come from § Motion Principles. Hard-coded magic numbers are a review finding"); `design-conventions.md § Motion Principles` (state change = `--duration-fast`).
- **Issue:**
  - `--duration-fast` is 120 ms in `app/globals.css:103`. The cards and pager use 150 ms, copied from `Button`.
  - The spec also says both "`--duration-fast`" and "the prototype's 0.15 s".
  - Consistency with `Button` is a fair reason, but the magic number now spreads.
- **Remediation:** Use `duration-(--duration-fast)`, or record 150 ms as the hover token. This is a site-wide question because of `Button` (see Convention drift).
- **Routed to:** Frontend Engineer; UX Strategist for the token.

#### Finding RV-0045: A client hook lives in `features/guias/lib/` rather than `hooks/`
- **Location:** `features/guias/lib/use-align-to-hash.ts`
- **Convention citation:** per `frontend-architecture-conventions.md § App Router Layout` (`features/<feature>/` → `components/ hooks/ …`). Sobre mí follows it (`features/sobre-mi/hooks/`).
- **Remediation:** Move it to `features/guias/hooks/use-align-to-hash.ts`. Keep `lib/active-section.ts` (a pure function) where it is.
- **Routed to:** Frontend Engineer.

#### Finding RV-0046: The aside index runs its scroll handler and re-renders at widths where it is `display: none`
- **Location:** `features/guias/components/guide-toc.tsx:27-54`
- **Convention citation:** per `frontend-architecture-conventions.md § Performance Budgets` (INP ≤ 200 ms; phone is the primary device).
- **Issue:**
  - At ≤960, the `<nav>` is hidden, but the `scroll`/`resize` listener still measures every H2 and calls `setActive` on each animation frame while scrolling. It is cheap (8 to 9 headings and a rAF throttle), but it is pure waste on the primary device.
  - `useAlignToHash` must keep running at every width, so this concerns only the active-section effect.
- **Remediation:** In `update`, return early when the nav has no layout box (`navRef.current?.offsetParent === null`), and recompute on `resize`.
- **Routed to:** Frontend Engineer.

## Convention drift (suggestions; convention files not edited)

- **Suggested convention update: § "Static content pages"** in `frontend-architecture-conventions.md`. Content as typed data in `features/<f>/content/`, a lean `meta` module whenever a client component needs a subset, and a fidelity test against the source document that also covers emphasis (see RV-0038). Sobre mí and Guías both do this now. The plan § 20 and the security report make the same suggestion.
- **Suggested convention update: § Animation / § Motion Principles.** State `--duration-fast` or `150ms` once for hover lifts. `Button`, cards and pager all use `duration-150` while the token is 120 ms (RV-0044).
- **Suggested convention update: § App Router Layout.** Allow, or forbid, cross-feature imports of motion scenes and attributes (`features/sobre-mi/motion/*` used by Guías). Plan § 20.2 proposes hoisting them to a neutral module.
- **Suggested convention update: § Design Tokens.** Structural container-query widths do not need a Token Proposal (plan Q2, accepted twice now).
