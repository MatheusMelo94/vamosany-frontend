## 3. Avaliação por tema (o que foi pedido explicitamente)

- **Estrutura e ordem dos jobs:** `check` (typecheck → lint → format → test → build) e `e2e` (`needs: check`, rebuilda e roda Playwright). Ordem correta; o rebuild no `e2e` é decisão registrada (`1ed6d6e`) e custa ~1 min. Sem job `lhci` (M2), sem smoke (M1).
- **Caching:** só `~/.npm`. Falta `.next/cache` e `~/.cache/ms-playwright` (B2).
- **`npm ci` + `npm audit`:** presentes e na ordem certa (audit antes de gastar minutos com typecheck). `--omit=dev` é a única ressalva (B10). `engine-strict=true` + `engines` garantem Node 24 em qualquer instalação.
- **Cobertura format/lint/typecheck/test/build:** completa (B8).
- **Job e2e:** instalação correta (`--with-deps chromium`), baseline comparado só no CI, report sobe em falha com trace embutido (B5). Retry 1 é a única ressalva.
- **`update-snapshots.yml`:** permissões corretas para o que faz (`contents: write` para o push, `pull-requests: write` para tirar a label, testado em `e38ff46`); trigger por label funciona; o problema é o `workflow_dispatch` poder escrever em `main` e o commit do bot ficar sem CI (A3). PRs de fork: `GITHUB_TOKEN` é read-only → push falha sem efeito colateral; irrelevante para repo solo.
- **Dependabot:** grupos `next` e `tooling` razoáveis; falta `ignore` de majors e `update-types`; 4 majors abertos contradizem decisões/engines (M4). Limite de 5 PRs abertos está bom.
- **Lighthouse CI:** config órfã (M2).
- **Smoke pós-deploy:** ausente (M1). O health route é `force-static` e devolve `{"status":"ok"}` — pronto para o `curl`.
- **Branch protection:** não verificável; é a condição principal (A1, § 6.1).
- **Tags e rollback:** tag ausente, rollback existe na Vercel mas não documentado (B1).
- **Secrets e env:** limpo (B12). Nenhum secret existe hoje; o guard (M6) deve entrar antes do primeiro.
- **Concurrency / timeouts:** presentes; `cancel-in-progress` em `main` é a ressalva (B3).
- **Pinning:** tags major, não SHA (A2).
- **Node/runner warnings:** nenhum esperado (B7).

name: CI

  workflow_dispatch: # usado por update-snapshots.yml para reanexar um check run ao commit do bot (A3)

  check:
    name: typecheck · lint · test · build
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0

      - run: npm run lint

      - uses: actions/cache@<sha-de-actions/cache-v5> # resolver com: git ls-remote --tags https://github.com/actions/cache.git
        with:

          restore-keys: next-${{ runner.os }}-${{ hashFiles('package-lock.json') }}-
      - run: npm run build

        run: |
          if grep -rEl "sk_(live|test)_|-----BEGIN [A-Z ]*PRIVATE KEY|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|xox[bp]-|AIza[0-9A-Za-z_-]{35}|re_[A-Za-z0-9]{20,}" .next/static; then
            echo "::error::possível secret no bundle do client"; exit 1; fi

      - name: Bundle guard (First Load JS ≤ 180 kB gzip por rota de página — arch § Performance Budgets)
        run: |
          node - <<'EOF'
          const fs = require("fs"), zlib = require("zlib");
          const budgetKb = 180; // owner: Architect. Nunca subir para deixar o CI verde.
          const m = JSON.parse(fs.readFileSync(".next/app-build-manifest.json", "utf8"));
          let failed = false;
          for (const [route, files] of Object.entries(m.pages)) {
            if (!route.endsWith("/page")) continue; // só rotas de página (ignora layout, route handlers, error)
            const kb = files.filter((f) => f.endsWith(".js"))
              .reduce((s, f) => s + zlib.gzipSync(fs.readFileSync(`.next/${f}`)).length, 0) / 1024;
            const over = kb > budgetKb; failed ||= over;
            console.log(`${over ? "✗" : "✓"} ${route}: ${kb.toFixed(1)} kB gzip`);
          }
          if (failed) { console.error(`First Load JS acima de ${budgetKb} kB — rota ao Architect.`); process.exit(1); }
