# Finding 0018: Oversized-hash branch of `useAlignToHash` is untested

- **Severity:** INFO
- **OWASP Top 10:2025:** A05 — Injection
- **Framework citation(s):** WSTG-CLNT-01 (DOM-based XSS); Cheat Sheet DOM-based XSS Prevention
- **Surface:** Client Component (tests)
- **Affected component:** `features/guias/lib/use-align-to-hash.ts:4-15` (`MAX_HASH`, `hashId`); `features/guias/__tests__/guide-toc.test.tsx:303-311`
- **Status:** Open
- **Posture:** Production
- **Blocking at this posture:** No

## Description
The hook's input handling is correct: length cap, guarded decode, allowlist lookup. The test suite pins the malformed-escape case (`#%E0%A4%A`) and the no-hash case, but not the length cap. A future refactor could drop the cap without a red test. Exploitability today is nil because the allowlist check alone already neutralises any hash; the cap is defense in depth.

## Evidence
`guide-toc.test.tsx:303` "never aligns without a hash, and never throws on a malformed one"; no case with a hash longer than 200 characters, and no case asserting that a hash equal to a valid id plus extra characters (`#tope<img>`) does not align.

## Impact
None today. Regression guard only.

## Likelihood
Hard (requires a future code change and the allowlist check to also regress).

## Remediation
Add two unit cases next to the existing one: a 5 KB hash, and a hash that is a valid id with appended markup; both must not scroll or throw. Per § Input & Output Handling.

## Remediation Route
- **Owner role:** Frontend Engineer
- **Reason routed there:** implementation (tests)

## Convention drift

No new security pattern beyond what the conventions and the Sobre mí review already cover. The Guías combination (compile-time `HttpsUrl` type plus a test-time scheme allowlist over every content href, and allowlisted hash lookup) is a good candidate to write down once as the standard for static content modules. Suggested convention update: add a short § "Static content modules" under § Input & Output Handling. Not modified in this review.
